README AGENT CLI: FILE STRUCTURE AND FILE PURPOSES
==================================================

This guide describes two different folders:

1. The readme-agent tool's own source-code project. You create and maintain
   this once when building the CLI.
2. A normal project where a user runs "readme-agent init". Only a small
   configuration file (and optionally a local Git hook) is added there.

The CLI's source-code project
-----------------------------

readme-agent/
|-- src/
|   |-- cli.ts
|   |-- config.ts
|   |-- commands/
|   |   |-- init.ts
|   |   `-- update.ts
|   |-- git/
|   |   `-- repository.ts
|   |-- readme/
|   |   |-- collectContext.ts
|   |   |-- updateReadme.ts
|   |   `-- preview.ts
|   `-- ai/
|       `-- provider.ts
|-- test/
|   |-- init.test.ts
|   |-- repository.test.ts
|   `-- updateReadme.test.ts
|-- .gitignore
|-- package.json
|-- package-lock.json
|-- tsconfig.json
`-- README.md

Source files and their uses
---------------------------

src/cli.ts
The program's entry point. It defines the terminal commands and options,
then calls the matching command implementation. For example, "readme-agent
init" calls commands/init.ts.

src/config.ts
Loads, validates, and saves the target project's .readme-agent.json file.
It supplies defaults and reports invalid settings clearly.

src/commands/init.ts
Implements "readme-agent init". It finds the Git repository root, checks for
existing setup, creates the config file, and can optionally set up a local
Git hook after asking the user.

src/commands/update.ts
Implements "readme-agent update". It coordinates Git change collection,
context selection, README drafting, preview, approval, and writing.

src/git/repository.ts
Finds the repository root and obtains status and diffs. It handles cases
such as running outside a Git repository or having no relevant changes.

src/readme/collectContext.ts
Selects the README and relevant changed project files to provide context.
It skips ignored files, secrets, dependencies, and build output, and applies
reasonable file-size limits.

src/readme/updateReadme.ts
Builds a focused README update and applies it only to the managed README
section. It preserves all README text outside that section.

src/readme/preview.ts
Creates a readable before/after diff, asks for approval, and passes the
approved change back to updateReadme.ts. It does not commit or push changes.

src/ai/provider.ts
Optional AI integration. It sends only selected context to the configured
model and returns a proposed edit. Keep provider-specific code here so it
can be replaced without changing Git or README handling. If the first
version uses templates only, this file can be added later.

test/init.test.ts
Checks that init creates the expected config and does not overwrite existing
settings without permission.

test/repository.test.ts
Checks repository detection and diff handling using temporary Git repos.

test/updateReadme.test.ts
Checks that updates affect only the marked README section and preserve the
rest of the document.

Root-level files
----------------
package.json
Names the npm package and its terminal command ("readme-agent"), lists
dependencies, and defines build, test, and development scripts. Its "bin"
setting connects the command name to the compiled CLI entry point.

package-lock.json
Generated by npm install. Records exact dependency versions so installs are
repeatable. Usually commit this file for an application or CLI package.

tsconfig.json
Configures TypeScript compilation, including the source and output folders.

.gitignore
Lists generated or local-only files that Git should not track, such as
node_modules/, dist/, test output, and local environment files.

README.md
Explains how to develop, test, install, and use the readme-agent CLI. This
belongs to the tool's source repository, not to an initialized user project.

Generated build output
----------------------
dist/
Created by the build command from src/. It contains the JavaScript that
Node.js runs when someone invokes the installed CLI. Do not edit dist/
directly; rebuild it from src/. It is usually excluded by .gitignore.

Files in a project initialized by the CLI
-----------------------------------------

my-project/
|-- .readme-agent.json
|-- README.md
`-- .git/
    `-- hooks/
        `-- post-commit       Optional; only if the user enables it

.readme-agent.json
Created by "readme-agent init". Stores settings for this repository, such as
the README path, eligible source paths, excluded paths, and update mode.
It must not contain API keys or other secrets. The CLI should preserve
existing settings when init is run again.

README.md
Usually already exists and belongs to the project owner. The CLI should
preserve it and edit only a clearly marked section, for example:

  <!-- README-AGENT:START -->
  Generated text maintained by readme-agent.
  <!-- README-AGENT:END -->

If README.md does not exist, init or update can offer to create it. The tool
should explain this before writing a new file.

.git/hooks/post-commit (optional)
Created only if the user explicitly enables post-commit updates. It runs
readme-agent after a commit and leaves any README change uncommitted for
review. Git hooks are local to that clone and are not shared when someone
clones the project. The tool must explain how to disable or remove the hook.

What init should NOT copy into the user's project
-------------------------------------------------
The user's project does not need the CLI's src/, test/, package.json,
node_modules/, or dist/ folders. Those belong to the separate readme-agent
tool project or its installation. Init should create only the project's
configuration and any explicitly enabled local integration.

Files to add later, if needed
-----------------------------
- src/commands/watch.ts: implement an optional watch command.
- src/watch/fileWatcher.ts: watch selected files and debounce repeated save
  events. A package such as chokidar can provide file watching.
- test/watch.test.ts: test that watch mode ignores README and generated files.
- A provider-specific AI module: add only when an AI service is selected.

Start with the required CLI files, init, update, Git diff handling, safe
README editing, and tests. Add watch mode, AI integration, and Git hooks
after the basic commands work.
